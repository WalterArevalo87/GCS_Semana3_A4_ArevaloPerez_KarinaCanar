# Solicitud de cambio CR-001
 
## 1. Identificación
 
| Campo | Detalle |
|---|---|
| Código | CR-001 |
| Fecha | 31 de julio de 2026 |
| Título | Incorporación de un requisito de rendimiento |
| Línea base afectada | v1.0 – commit `c17712f` |
| Prioridad | Media |
| Estado | En implementación |
| Solicitante | Equipo del proyecto |
| Responsables | Desarrollo y QA |
 
## 2. Descripción del cambio
 
Se solicita incorporar un requisito no funcional de rendimiento para comprobar la capacidad de respuesta del prototipo ATM. El sistema deberá completar, en las condiciones definidas para la prueba, al menos 95 de 100 operaciones en un tiempo máximo de dos segundos por operación.
 
## 3. Justificación
 
La línea base `v1.0` contiene requisitos funcionales y pruebas relacionadas con autenticación, consulta de saldo y retiros; sin embargo, no establece un criterio medible de rendimiento. El cambio permitirá evaluar el tiempo de respuesta mediante una métrica objetiva y conservar evidencia verificable de su cumplimiento.
 
## 4. Elementos de configuración afectados
 
| Elemento | Modificación prevista |
|---|---|
| `docs/SRS/SRS_ATM_v1.md` | Incorporar el requisito `RNF-PERF-01`. |
| `docs/Quality/Quality_Model.md` | Añadir la métrica `MC-PERF-01`. |
| `tests/test_atm.py` | Incorporar la prueba `TEST-PERF-01` con 100 operaciones. |
| `CHANGELOG.md` | Registrar la implementación del cambio. |
| `src/atm.py` | Modificar únicamente si la prueba evidencia la necesidad de optimización. |
 
## 5. Análisis de impacto
 
El cambio no altera las funciones disponibles ni la estructura principal del prototipo. Su impacto se concentra en la documentación, la medición de calidad y las pruebas. La línea base `v1.0` permanecerá intacta, ya que la implementación se registrará en commits posteriores y en la rama `change/cr-001-rendimiento`.
 
## 6. Riesgos y controles
 
| Riesgo | Control |
|---|---|
| Variación del tiempo según el equipo de ejecución | Utilizar un reloj de alta precisión y registrar las condiciones de la prueba. |
| Inconsistencia entre requisito, métrica y prueba | Mantener trazabilidad mediante los códigos `RNF-PERF-01`, `MC-PERF-01` y `TEST-PERF-01`. |
| Afectación de funciones existentes | Ejecutar nuevamente todas las pruebas funcionales. |
 
## 7. Criterios de aceptación
 
- El requisito `RNF-PERF-01` se encuentra documentado.
- La métrica `MC-PERF-01` define la forma de cálculo.
- `TEST-PERF-01` ejecuta y mide 100 operaciones.
- Al menos 95 operaciones finalizan en un máximo de dos segundos cada una.
- Las 11 pruebas funcionales existentes continúan aprobándose.
- El cambio queda registrado en `CHANGELOG.md`.
- La línea base `v1.0` permanece sin modificaciones.
 
## 8. Trazabilidad

## 9. Reversión
 
Si el cambio produce errores o resultados inconsistentes, se revertirán los commits asociados a `CR-001`. El tag `v1.0` permitirá recuperar la versión estable anterior.
